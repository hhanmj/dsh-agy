## 2. 功能 A 调研

### 2.1 DSH 的会话事件约束（0.2.0-rc.2）

- `Session.append(type, data, ...opts)` 构造的事件信封只有 `type/seq/time/data`（以及消息类事件的 surface 元数据），**没有设置 `ignorable` 的参数**。
- 持久化读取时，`validateStoredEvents` 对不在 `KNOWN_SESSION_EVENT_TYPES` 且未标记 `ignorable: true` 的事件抛出 `SessionFormatUnsupportedError`，即**整个会话无法重新打开**。
- 上游《Harness plugin practices》明确写道：不要追加新 `type` 的会话事件；应从已有事件推导状态，或把插件数据放在自己的存储中。
- 因此需求 A2 中“`session/event` 持久化执行生命周期事件”**在当前版本不能直接实现**，否则会损坏用户会话。

### 2.2 Client 扩展点（0.2.0-rc.2 已具备）

- 事件定义：`ctx.uiConversation.events.register(ConversationNodeDefinition)`，按 `(kind, id)` 关联 start/update，支持实时与历史分页重放。
- 渲染：`ctx.slots.inject('conversation.chat.node', () => ctx.slots.register({ name: 'conversation.chat.node', key: kind }, View))`。
- 打包：`package.json` 增加 `dsh.client` 与 `exports['./client']`；产物以 `window.__ModuleLoader__.load({ id, factory })` 注册，React 等作为外部依赖；上游建议不要 require 其他 Harness Client 包，样式只用 `--dsw-alias-*` 主题变量。
- 但 Chat 节点只能从**会话事件**构建；第三方插件没有安全的持久事件来源（见 2.1），也没有面向第三方的 Host→Client 数据通道（typert 远程 API 依赖仓库内代码生成；会话投影 `wire.view` 只能纯函数折叠已有事件）。

### 2.3 可选路径

| 路径 | 实时 | 刷新后重建 | 代价 / 风险 |
|---|---|---|---|
| A-1 当前方案：运行中进度行 + 结束时消息内 GenUI 折叠面板 | 仅已完成步骤（文本行） | ✅（随助手消息保存） | 已实现；无法原地更新运行中步骤 |
| A-2 Jobs 面板：每轮 AGY 执行登记为 DSH Job，实时输出步骤 | ✅（原生 Jobs UI） | 取决于 Jobs 历史保留 | 不在对话流中；需验证主对话场景的 Job 语义 |
| A-3 升级 DSH ≥ 0.2.1-rc.2，用 `plugin:agy/activity` 插件记录 + 自有 Chat 节点 | ✅ ACTIVE/DONE/ERROR 原地更新 | ✅（迁移时尽力保留，丢失只影响展示） | 需升级 DSH；上游政策把该 API 保留给仓库内实验性包，需确认可接受 |
| A-4 等待上游为第三方插件提供可持久化事件或 Host→Client 通道 | ✅ | ✅ | 时间不可控，可向上游提需求 |

**建议**：保持 A-1 作为 0.2.0-rc.2 的默认方案；Phase 1 先实现统一事件模型（AgyActivityEvent，按 `sessionId + runId + stepIndex` 合并状态，复用 trace 的脱敏/截断），使其能同时驱动 A-1 和后续的 A-3；是否采用 A-3 取决于是否升级 DSH 以及能否接受上游政策限制。

### 2.4 协议边界（不变）

不把 AGY `tool_info` 伪装成 DSH `tool-call-delta`；不伪造思考链（已实测：stream-json 只有 `thinking_tokens`，PreInvocation/PostInvocation 钩子载荷无思考字段）。

## 3. 功能 B 调研

### 3.1 官方协议要点（AGY Headless 文档 “Stream prompts from stdin”）

- 启动：`agy --input-format stream-json --output-format stream-json`（**不能带 `-p`**，带了会被忽略）；模型、effort、agent 等为启动参数。
- 输入：每行一个 `{"event":"user","message":{"content":"..."}}`；须等到当前轮的 `result` 再写下一条。
- 输出：进程只发一次 `init`；每轮若干 `step_update` + 一个 `result`。`result.response` 只属于本轮；**`num_turns`、`usage`、`duration_seconds` 为会话累计值**。
- 结束：关闭 stdin，进程在当前轮结束后退出，退出码 0。
- 输入校验：未知 event 名跳过并在 stderr 警告；`control_request/control_response` 与可由 CLI 直接处理的斜杠命令 → ERROR 结果并退出 2；缺少 event 字段、非法 JSON、非文本内容块 → ERROR 结果并退出 1。
- 状态值：SUCCESS / ERROR / CANCELED / INTERRUPTED / INVALID / WAITING / RUNNING。
- 协议中**没有取消单轮的消息**；取消只能终止进程（与需求 B4 的预期一致）。图片仍须以文件路径文本传递（非文本内容块会终止会话）。

### 3.2 DSH 子进程能力

dsh-subprocess：`stdio.stdin: 'pipe'` 时 `SubprocessHandle.stdin` 为 Writable，stdout 可流式读取，`terminate()` 结束进程树。满足常驻会话需要。

### 3.3 Mock 验证（`node scripts/phase0-persistent-probe.mjs`，10/10 通过）

Mock CLI（`scripts/helpers/mock-agy-stream.mjs`）按文档实现协议，验证了：同一进程三轮共享 conversation_id；`num_turns` 累计；单轮用量 = 累计差分；单轮 response 等于本轮 text_delta；工具 ACTIVE/DONE；单轮 ERROR 不结束会话、未知事件被跳过；关闭 stdin 后先收到在途结果再以 0 退出；轮中终止无 result 且非 0 退出；非法 JSON → ERROR 并以 1 退出；两个会话并发隔离；新进程可在已存 conversation_id 上启动（真实 CLI 待验证）。

### 3.4 设计要点（Phase 2）

- `PersistentAgySessionManager`：DSH 会话 → { 进程、conversation_id、启动配置键（模型/effort/cwd/附加目录/监督目录/权限）}；配置变化时安全重建；同会话串行排队、不同会话并发；空闲回收；默认关闭（feature flag），保留 one-shot 回退。
- 轮次边界以 `result` 判定；`AgyStreamAccumulator`/`TurnUsage` 改为每轮独立状态，用量用累计差分。
- 取消：终止进程，本轮记为 cancelled；下一轮用新进程 + `--conversation` 从最后完成的轮次继续，不假设未完成轮次可恢复。
- 复用：模型选择、trace（每轮一个 run）、监督钩子（每进程一个监督目录）、工作区证据（每轮）、图片（文件路径）。

### 3.5 ACP 对比（未实测）

官方注册表中的 `antigravity-acp` 1.4.0 是**独立的专有二进制**（`agy-acp-server`，从 dl.google.com 下载，本机未安装）。ACP 协议本身定义了 JSON-RPC 会话、提示、工具调用状态更新以及会话取消，理论上可提供“取消单轮而不杀进程”和结构化工具状态；但 Antigravity 实际发出哪些更新、许可与稳定性均未验证。**建议 Phase 2 采用已安装且有文档的 CLI streaming**，ACP 作为后续调研项。

## 6. 维护者决定与 v0.4.2 实现（2026-10-17）

决定：不升级 DSH（担心插件与核心冲突导致无法启动），按 v0.4.2 推进；授权真实账号小规模测试。

### 6.1 真实 CLI 验证（`node scripts/live-persistent-probe.mjs`，全部通过）

- 同一进程只发一次 `init`，4 轮共享 conversation_id；每轮 `result.response` 只含本轮且等于本轮 text_delta。
- `num_turns` 1→4 累计；`result.usage.input_tokens` 16686→18819→20950→23080 累计，差分恰等于各轮 step 级用量之和。
- **新发现：** 续接会话（无论 one-shot `--conversation` 还是新的 streaming 进程）时，`result.usage`/`num_turns` 按**整个对话**累计（恢复后首轮 num_turns=8）。因此单轮用量必须取 step 级计数，不能用进程内差分。v0.4.1 的 one-shot 续聊因此会把输出 token 报成累计值，v0.4.2 已修正。
- 工具 ACTIVE/DONE 在本轮内到达；未知输入事件被跳过；轮中终止 → 无 result、退出码 1；新 streaming 进程 + `--conversation` 可恢复历史；关闭 stdin 先交付在途结果再以 0 退出。
- 延迟（各 3 次，gemini-3.8-flash low）：一次性续聊中位数 6754 ms；常驻续轮中位数 2230 ms；进程启动到 init 3.4–5.5 s。

### 6.2 实现

- **功能 A（等效 UI，不写会话事件）**：`src/activity.ts` 统一活动模型（按 sessionId + runId + stepIndex 合并 ACTIVE/DONE/ERROR，脱敏截断，未知类型保留原始标识，统计 thinking_tokens）。主对话运行中实时显示工具步骤的开始/完成/失败，结束时由消息内 GenUI 折叠面板替代（随消息持久，重新打开可见）。子代理：仅 trace（其最终回复会返回父代理，面板会成为父模型的噪声）。
- **功能 B**：`src/persistent.ts` 的 `PersistentAgyProcess` / `PersistentAgySessionManager`，接入原生适配器（主对话与子代理）；`nativePersistentSessions` 默认关闭，`nativePersistentIdleMs` 默认 10 分钟；启动参数键变化即重建（带 `--conversation`）；取消 = 终止进程、本轮记为 cancelled；以 `/` 开头的消息与标题/压缩请求走一次性进程；不支持 streaming input 的版本自动回退；插件停止时终止全部进程；监督钩子每进程一个目录、每轮切片决策；`antigravity_tasks` 显示常驻进程。
- **测试**：离线 70 项（含 Mock CLI 真子进程的管理器/适配器测试：复用、串行与并发隔离、重建、空闲回收、取消/超时/进程丢失、dispose 后无残留进程、后端重启恢复、斜杠命令回退、无 streaming 回退、续聊用量）。真实 AGY：`scripts/live-persistent-e2e.mjs` 通过（5 轮同一进程、工具步骤实时显示、停止后恢复；热进程续轮中位数 2442 ms，一次性续聊中位数 6884 ms）。
